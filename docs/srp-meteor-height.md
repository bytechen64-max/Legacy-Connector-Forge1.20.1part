# SRP meteor placement below Y=0

SRP 1.10.9 uses absolute Y=5/6 guards for meteor crater carving, the main sphere's minimum center and the structure/pool floor. A modern superflat surface is Y=-60. The guards moved the meteor body to positive Y rather than to the impact area. Its entity also treated Y<=0 as the bottom of the world.

`SrpMeteorHeightFix` changes only the relevant meteor classes' floor expressions and Y comparisons. Stage numbers, radius divisors and unrelated generators remain unchanged. The runtime helper adds each original margin to the actual world's minimum build height. The transformer cache version is incremented so existing installations retranslate SRP automatically.

Validation uses an isolated Forge 1.20.1 server with the real, unmodified SRP 1.10.9 jar. The script `tools/dev/srp/meteor-structures.js` checks template reading/placement, a moving fragment, a main meteor at Y=64, and a main meteor over a platform at Y=-60. Run with `runServer -PrunDir=<isolated-directory> --init-script tools/dev/srp/meteor-test.init.gradle`. The directory must contain an accepted EULA, a fresh test world, and the SRP jar under `mods/.legacyconnector/originals/`. Never point this test at a player's save; it deliberately creates meteor impacts and stops the server afterward.

Before the fix, the negative-height impact produced 586 parasite blocks below zero (including the origin) and 4633 above zero. After the fix in a fresh world: 5208 below zero and none above zero. The positive-height main meteor produced 4659 parasite blocks. Three loader unit tests also verify floor matching and preservation of stage/radius constants. Logs: `build/meteor-negative-before.log`, `build/meteor-negative-after.log`, `build/meteor-height-unit.log`.

A plain `/summon srparasites:meteor` has no initial velocity. For an immediate falling test use `/summon srparasites:meteor ~ ~10 ~ {Motion:[0.0d,-1.0d,0.0d]}`. The original 1200-tick timeout remains in place. Already completed impacts are not regenerated by this fix.
